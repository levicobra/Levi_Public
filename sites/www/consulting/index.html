Palantir, government, AI.

XPLabs builds on Palantir Foundry, Gotham and AIP, and takes on public-sector consulting, custom software and AI implementation — with a bias toward systems that still work when nobody is watching them.

PalantirFoundry · Gotham · AIP

Foundry development

The ontology is the product. Objects, links and actions modelled so the data reads the way the mission talks about it — not the way the source system happened to store it.

  • Ontology design: objects, links, action types
  • Pipeline Builder and code repositories (PySpark, TypeScript)
  • Incremental transforms, data health checks, branch and merge
  • Workshop applications an operator can run a shift from

AIP with review gates

The same rule as every other model we put into production: a result a human has not signed off on is not an answer, it is a suggestion. AIP Logic and agents are built to that standard or they do not ship.

  • AIP Logic functions bound to ontology actions
  • Agents scoped to a task, not to the whole estate
  • Evaluation sets before deployment, not after
  • Write-back that records who approved it

Gotham & integration

Getting real sources into the platform and keeping them there: the unglamorous half of every deployment, and the half that decides whether anyone still trusts it in month six.

  • Entity resolution and link analysis workflows
  • Data connection, sync health, schedule design
  • Permissioning and markings that survive an audit
  • Handover documentation for the team that inherits it

Palantir work is forward-deployed by nature: the useful version is built next to the people who will use it, in the platform, against their real data — not specified in a document and handed over. That is the same delivery model the rest of this page argues for, which is why it is the platform work XPLabs takes on.

Honolulu is a deliberate part of this. XPLabs sits in the same time zone as INDOPACOM, Pacific Fleet and U.S. Army Pacific — the Indo-Pacific commands are a workday away rather than six hours behind, which matters for the kind of embedded work that only functions when you are reachable during the user's shift.

MethodHow it is built

Everything ships behind an automated test suite and a versioned build that lands on a real device. Content and code are separated, so a non-programmer can change a page, a lesson or a resource without touching a line of logic.

The web work is deliberately dependency-free. XP Education serves 106 subjects as plain files with a service worker; this site is hand-written HTML. Neither has a package manager, a bundler, or a version that can drift. That is a maintenance decision, not a technical limitation — the hard part of a small system is not building it, it is opening it again six months later.

You do not have to take any of this on trust. The games catalog documents four titles at equal depth, and both public initiatives are live, free and inspectable.
