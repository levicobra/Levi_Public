Consulting · technical record

Four stacks. No house framework.

Each project uses what actually suits it rather than one studio stack. A survivors game and a benefits directory have nothing in common, and pretending otherwise costs more than it saves.

StackWhat gets used, and where

Unreal Engine 5 · C++Mobile-first, forward renderer, small handcrafted zones, async-only backend.
Swift 6 · SpriteKitA deterministic game engine with its own test suite, StoreKit 2, and on-device analytics only.
SwiftUI · SceneKitA pure simulation core that does not depend on the UI layer, so saves survive a rewrite of the front end.
Roblox · LuauServer-authoritative, versioned player profiles, validation on the server side.
Static HTML · no buildThis site and XP Education. No framework, no npm, no build step — nothing that can rot between releases.
AI-augmented pipelineUsed throughout, with human review gates. It is how a team this size ships across four stacks at once.

MethodHow it is built

Everything ships behind an automated test suite and a versioned build that lands on a real device. Content and code are separated, so a designer can change a card, a lesson or a resource without touching a line of logic.

The web work is deliberately dependency-free. XP Education serves 106 subjects as plain files with a service worker; this site is hand-written HTML. Neither has a package manager, a bundler, or a version that can drift. That is a maintenance decision, not a technical limitation — the hard part of a small project is not building it, it is opening it again six months later.

You can check all of this rather than take it on trust: the catalog documents every title at equal depth, and both free products are live and inspectable.
