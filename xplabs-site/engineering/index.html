Engineering

Four games, an offline school and a public benefits directory — built and shipped by a small team across five different stacks.

What gets used

Each project uses whatever actually suits it rather than one house stack. That is a deliberate choice: a survivors game and a benefits directory have nothing in common, and pretending otherwise costs more than it saves.

Unreal Engine 5 · C++The Last Station. Mobile-first, forward renderer, small handcrafted zones, async-only backend.
Swift 6 · SpriteKitSpace Glyph. Deterministic game engine with its own test suite, StoreKit 2, on-device analytics only.
SwiftUI · SceneKitLife XP. A pure simulation core that does not depend on the UI layer, so saves survive a rewrite of the front end.
Roblox · LuauHearth & Hunt. Server-authoritative, versioned player profiles, validation on the server side.
Static HTML · no buildXP Education and this site. No framework, no npm, no build step — nothing that can rot between releases.
AI-augmented pipelineUsed throughout, with human review gates. It is how a team this size ships across five stacks at once.

How it is built

Everything ships behind an automated test suite and a versioned build that lands on a real device. Content and code are separated so a designer can change a card, a lesson or a resource without touching a line of logic.

The web work is deliberately dependency-free. XP Education serves 106 subjects as plain files with a service worker; this site is hand-written HTML. Neither has a package manager, a bundler, or a version that can drift. That is a maintenance decision, not a technical limitation — the hard part of a small project is not building it, it is opening it again six months later.
